# ChemLab-G9 V1.7 Engine Boundaries

## Purpose

The `engine/` directory is a domain-engine layer, not an application composition layer. V1.7 keeps domain engines that are consumed by controllers while application concerns remain under `app/`, and presentation remains under `views/`.

## Current domain engines

- `assessment-engine.js` — evaluates assessment answers and produces answer evidence.
- `experiment-engine.js` — manages experiment definitions, sessions, observations, validation and completion.
- `canonical-knowledge-engine.js` — owns canonical knowledge nodes and relations.
- `mastery-engine.js` — maintains canonical mastery evidence/state.

## Boundary rules

1. `app/bootstrap.js` owns browser startup and the published `#app-root` entrypoint.
2. `app/application.js` is the composition root and wires controllers, services and views.
3. Controllers coordinate user flows; they do not duplicate domain algorithms.
4. Domain engines in `engine/` must not query the DOM or own browser lifecycle state.
5. Content loading belongs to the `app/` content boundary. `engine/content-loader.js` is retained only as a compatibility shim during migration and must not regain business logic.
6. Views render data and callbacks; they do not mutate canonical domain state directly.
7. Diagnosis is canonicalized separately and feeds remediation/recheck rather than being duplicated inside assessment or experiment engines.

## Runtime flow

```text
index.html
  -> app/bootstrap.js
  -> app/application.js
  -> controllers
  -> services / domain engines
  -> views
```

Learning evidence follows:

```text
Assessment / Experiment
  -> evidence
  -> canonical mastery / diagnosis
  -> remediation
  -> targeted recheck
  -> new evidence
```

## Cleanup policy

A file under `engine/` is removable only when:

- no production import remains;
- no test import remains;
- its behavior has a canonical replacement;
- the replacement has regression coverage;
- the full V1.7 baseline remains green.

This prevents the legacy cleanup from deleting domain behavior merely because an older filename or comment still exists.
