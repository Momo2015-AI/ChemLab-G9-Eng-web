# V1.7 Phase 1.7 — View Layer Extraction

## Completed

The main application-facing views now have explicit rendering modules:

```text
views/
├── home-view.js
├── course-view.js
├── quiz-view.js
├── experiment-view.js
├── dashboard-view.js
└── graph-view.js
```

## Boundary

Views receive prepared data and callbacks. They do not own:

- persistence
- content fetching
- assessment decisions
- mastery calculations
- experiment domain rules
- curriculum rules

## Why this matters

The same learning model can now be rendered by a web view without coupling chemistry logic to DOM code. This is also the foundation for accessibility, responsive layouts, and future alternate presentation modes.

## Migration status

`engine/app.js` remains as a compatibility runtime. The next step is application composition: connect router, state, services, controllers, and views through `app/bootstrap.js` / `app/application.js`, then run browser smoke checks before removing legacy rendering responsibilities.

## Content design guardrail

A view is not allowed to invent pedagogical meaning. If a concept, misconception, experiment interpretation, or learning objective is important, it must come from structured content or a domain service.
