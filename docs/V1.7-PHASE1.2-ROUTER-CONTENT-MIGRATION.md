# ChemLab-G9 V1.7 Phase 1.2 — Router & Content Migration

## Goal

Move application navigation and content access behind explicit boundaries without deleting the V1.6 engine.

## Completed

- Added `app/router.js` as the application routing boundary.
- Added `app/content-service.js` as the application content boundary.
- Kept `engine/router.js` and `engine/content-loader.js` intact for backward compatibility.
- No lesson, question, experiment, or knowledge data was modified.

## Current transition

```text
index.html
   ↓
app/bootstrap.js
   ↓
app/router.js ───────────────┐
   ↓                         │
application state            │
   ↓                         │
app/content-service.js       │
   ↓                         │
engine/content-loader.js ←──┘
   ↓
modules/ + content/
```

## Why this is deliberately incremental

`engine/app.js` currently owns routing state, rendering, progress, assessment, experiments, and data access. Replacing those responsibilities in one commit would create a high regression risk.

The migration therefore follows this order:

1. Establish boundaries.
2. Add adapter/service layers.
3. Move callers one responsibility at a time.
4. Add validation and smoke tests.
5. Remove legacy responsibilities only after callers have migrated.

## Next migration targets

1. Change bootstrap to create the router and content service.
2. Replace direct `currentPage` navigation with route state.
3. Move lesson/question lookup calls from `ChemLabApp` to `ContentService`.
4. Extract rendering into view modules.
5. Extract quiz/session state into an assessment controller.
6. Extract experiment session state into an experiment controller.
7. Remove obsolete `engine/router.js` only after all callers are migrated.
