# V1.9 Content Audit Metrics

## Purpose

Turn content completeness into measurable project data. File existence, question count, and page count are not accepted as evidence of learning completeness.

## Primary metrics

### Lesson real-content coverage

`real lessons / total lessons × 100%`

A lesson is real only when its primary teaching sections contain specific, topic-dependent chemistry content and do not match the project placeholder patterns.

### Lesson readiness coverage

`ready lessons / total lessons × 100%`

### Question verified coverage

`verified or ready questions / non-quarantined questions × 100%`

### Placeholder rate

`placeholder items / scanned items × 100%`

### P0/P1 defect count

Count unresolved blocking and pre-publication defects.

### Misconception coverage

`knowledge points with ≥1 reviewed misconception / knowledge points requiring misconception modeling × 100%`

### Diagnostic linkage coverage

`questions with valid misconception links where applicable / eligible diagnostic questions × 100%`

### Remediation loop coverage

`misconceptions with remediation + recheck / reviewed misconceptions × 100%`

### Knowledge-link integrity

`valid references / all references × 100%`

Target: 100% before release.

## Initial audit baseline

The project currently treats the 36 lesson files as an audit target. The baseline must be generated by the automated scanner rather than manually inferred.

The expected report format is:

```text
Lessons scanned: N
Real-content lessons: N
Template lessons: N
Ready lessons: N
Lessons requiring rewrite: N

Questions scanned: N
Verified/ready: N
Quarantined: N
P0: N
P1: N

Misconceptions: N
Knowledge points with misconception coverage: N/N
Remediation loops complete: N/N

Broken references: N
```

## Release thresholds

- Template lessons: 0
- P0 defects: 0
- Broken references: 0
- Published content without required evidence: 0
- Knowledge-link integrity: 100%
- Benchmark lesson: 100% review gate

Other percentages are tracked during production and must meet the release plan before public launch.

## Anti-gaming rule

Adding files, increasing question counts, or increasing text length does not improve a metric unless the underlying content passes the relevant review gate.
