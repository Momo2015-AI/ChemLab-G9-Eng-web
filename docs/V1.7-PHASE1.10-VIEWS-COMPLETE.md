## Shared constants module

`views/constants.js` provides the canonical `MODULE_CONFIG` and helper functions used across views:

- `MODULE_CONFIG` — module IDs, names, colors, prefixes, order
- `getNodesByModule(nodes, modId)` — filters knowledge graph nodes by module
- `computeModuleMastery(nodes, modId, progress)` — average mastery per module
- `computeDayMastery(day, progress)` — average mastery for a day's knowledge points

## View contract (enforced)

Views must NOT:
- Call `localStorage` directly
- Fetch data via `fetch()`
- Contain assessment or mastery logic
- Contain chemistry curriculum rules

Views receive:
- Pre-fetched data objects
- Callbacks for user actions (via `data-action` attributes)

## Action binding

The application composition root (`app/application.js`) calls `bindActions(root)` after each render. This wiring:
- Listens for `data-action` attributes on elements
- Routes actions to controller methods or router navigation
- Supports: `go-home`, `go-course`, `go-graph`, `go-dashboard`, `start-quiz`, `start-quiz-by-node`, `retry`, `continue`, `back`, etc.

## Migration status

The production entry point (`index.html`) now loads `app/bootstrap.js` instead of `engine/app.js`. Legacy `engine/app.js` remains on disk as a reference but is no longer executed.
