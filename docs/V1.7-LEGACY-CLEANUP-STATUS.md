# V1.7 Legacy Cleanup Status

> Status: active audit
> Principles: first principles, KISS, long-term maintainability, preserve the scientific learning loop.

## 1. Purpose

This document is the current source of truth for V1.7 legacy cleanup. A legacy file is not deleted merely because it has no importers. Deletion requires evidence that it has no production entry point, test dependency, deployment entry point, or unique educational value.

The protected learning loop is:

```text
Learning
  -> Assessment / Experiment
  -> Evidence
  -> Mastery
  -> Diagnosis / Remediation
  -> Targeted Recheck
  -> New Evidence
  -> Transfer
```

Any cleanup that breaks this loop is rejected.

## 2. Confirmed production architecture

```text
index.html
  -> app/bootstrap.js
  -> app/application.js
      -> controllers
      -> app services
      -> views

AssessmentController
  -> MasteryService
  -> MasteryEngine
  -> learning state

ExperimentController
  -> experiment engine
  -> observation validation
  -> MasteryService

LearningController
  -> remediation engine
  -> targeted recheck
  -> AssessmentController
```

Dashboard is a read model and presentation layer:

```text
MasteryService
  -> progress projection
  -> DashboardView
```

Knowledge graph access is centralized through the canonical knowledge engine exposed by ContentService.

## 4. Lab rule

The old LAB runtime must not become a second experiment application. Its runtime code can be deleted after content verification. Educational assets such as experiment objectives, equipment, observations, safety notes and equations must be preserved or migrated into the V1.7 content model first.

## 5. Test protection

The following learning-loop areas now have controller-level tests:

- Assessment answer -> mastery evidence
- Experiment validation/observation -> mastery evidence
- Remediation -> targeted recheck -> assessment evidence

These tests are intended as architectural guardrails, not merely coverage metrics.

## 6. CI requirements

Current CI performs:

1. JavaScript syntax checking
2. `npm test`
3. JSON parsing validation
4. `index.html` entry-point validation

Schema validation remains a follow-up task after test stability is restored.

### Baseline gate

A baseline is considered GREEN only when a real GitHub Actions run for `main` reports success for all required checks. Static inspection is not treated as a test result. The current task is to obtain and inspect that run before declaring the baseline complete.

## 7. Rules for further cleanup

1. Do not delete based on directory name alone.
2. Do not create a new Engine/Manager/Service to replace a small amount of duplicated code.
3. Prefer one canonical domain implementation per concept.
4. Preserve educational semantics even when deleting technical implementations.
5. Every deletion must be followed by reference/search verification.
6. Every learning-domain change must have a test protecting the evidence flow.
7. Documentation must describe the current code, not a historical architecture.
