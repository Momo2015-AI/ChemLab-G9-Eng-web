# V1.7 Phase 1.3 — Application Decomposition

## Objective

Reduce `engine/app.js` from a monolithic application coordinator into a thin composition layer.

## New boundaries

```text
controllers/
├── learning-controller.js
├── assessment-controller.js
└── experiment-controller.js

app/
├── bootstrap.js
├── router.js
├── state.js
└── content-service.js

engine/
└── domain engines
```

### Responsibilities

**Application layer**
- startup
- dependency wiring
- route lifecycle
- shared application state

**Controllers**
- learning workflow
- assessment session
- experiment session

**Domain engines**
- assessment rules
- experiment rules
- diagnosis/mastery algorithms

**Views**
- DOM rendering only
- no direct data fetching
- no localStorage ownership

## Migration rule

Do not rewrite `engine/app.js` in one operation.

For each responsibility:

1. Create a controller.
2. Verify the controller against existing domain APIs.
3. Migrate one caller.
4. Add smoke coverage.
5. Remove the old responsibility from `engine/app.js`.

## Current extraction

- `AssessmentController` owns quiz session lifecycle.
- `ExperimentController` owns experiment session lifecycle.
- `LearningController` owns lesson/progress coordination.

The legacy app remains active until all callers have migrated.

## Important educational constraint

Controllers must not contain chemistry content or pedagogical rules. Those belong in structured content and domain services. This separation allows the learning model to evolve independently from UI code.
