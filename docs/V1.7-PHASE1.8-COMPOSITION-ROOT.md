# V1.7 Phase 1.8 — Composition Root

## Completed

The new application boundary is now wired through `app/bootstrap.js` and `app/application.js`.

```text
bootstrap
  ├── State
  ├── ContentService
  ├── Router
  ├── LearningController
  ├── AssessmentController
  ├── ExperimentController
  └── Views
```

Legacy `engine/app.js` is still loaded after the new boundary is initialized so the existing public runtime remains available during migration.

## Important compatibility decision

The existing assessment and experiment modules export singleton engine instances as their default exports. The composition root therefore injects those instances instead of constructing a second engine with `new`.

This prevents duplicated mistake/session state and keeps the migration aligned with the current engine API.

## Next verification phase

Before removing legacy responsibilities, verify these browser flows:

1. application bootstrap
2. home route
3. course route + lesson loading
4. quiz start → answer → score
5. experiment start → observation → completion
6. dashboard rendering
7. knowledge graph rendering
8. persisted state compatibility

Only after those flows are stable should rendering responsibilities be deleted from `engine/app.js`.
