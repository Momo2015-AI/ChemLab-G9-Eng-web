# V1.8 Directory Freeze Audit

## Status

**PASS — Directory Freeze baseline established**

Date: 2026-08-11
Repository: `Momo2015-AI/ChemLab-G9-Eng-web`
Branch: `main`

## Scope

This audit freezes the V1.8 repository layout after the V1.7 architecture reorganization and the subsequent legacy cleanup.

The audit covers:

- production entry points
- production import boundaries
- obsolete runtime files
- obsolete LAB implementation files
- transitional view registries/constants
- duplicate knowledge-engine layers
- duplicate progress/recommendation/task engines
- GitHub Pages deployment workflow
- regression guards for future changes

## Canonical production boundary

```text
index.html
  -> app/bootstrap.js
  -> app/application.js
  -> controllers/
  -> services/
  -> core/ canonical engines
  -> views/
```

`index.html` must not load the historical `engine/app.js` runtime.

## Confirmed cleanup

The repository history records removal of the obsolete V1.5/V1.6 runtime layers, including:

- V1.5 progress manager
- V1.5 recommendation engine
- V1.5 task engine
- obsolete knowledge graph builder/initializer/query/loader/node/relation/registry layers
- obsolete V1.6 application and backup
- obsolete V1.6 engine router
- obsolete V1.6 LAB state, experiment player, diagnosis, renderer, equipment registry and stylesheet
- obsolete LAB page
- obsolete transitional view registry
- obsolete view module constants

These removals preserve the canonical V1.7/V1.8 service/controller/engine boundaries rather than introducing replacement parallel implementations.

## Compatibility exception

The legacy content loader remains only as a compatibility shim. It is not a second application runtime and is not a second knowledge engine. Canonical content remains the preferred source.

The knowledge graph migration also retains a controlled legacy fallback for old data compatibility. New production content must use the canonical knowledge graph contract.

## Single-source rules

### Knowledge

Canonical knowledge graph and canonical `KnowledgeEngine` are the only production graph authority.

### Mastery

`MasteryEngine` owns mastery calculation. `MasteryService` delegates to it and does not maintain a second calculation model.

### Progress

`ProgressService` owns persistence/restoration of learner progress. Dashboard data is projected from canonical progress/mastery state.

### Diagnosis

The diagnosis engine is the canonical learning-evidence diagnosis boundary.

### Remediation

Remediation is derived from canonical content/diagnosis contracts and is not maintained as an independent learning engine.

## Regression protection

`tests/directory-freeze-v18.test.mjs` now guards the freeze by asserting:

1. obsolete runtime files are absent;
2. production source does not import removed legacy runtime modules;
3. `index.html` uses `app/bootstrap.js` and not `engine/app.js`;
4. the single-repository GitHub Pages workflow exists.

These checks run through the existing `npm test` test glob.

## CI / deployment

GitHub Pages deployment is configured as a single-repository workflow and is gated by the test suite before deployment.

The repository therefore follows:

```text
main
  -> npm test
  -> GREEN
  -> GitHub Pages deploy
```

## Remaining intentional compatibility

The following are intentionally retained until a future major migration explicitly removes backward compatibility:

- legacy content loader shim
- legacy content/data fallback paths required for migration
- legacy progress-storage compatibility where existing learner data must remain readable

These are adapters/compatibility boundaries, not parallel production engines.

## Freeze decision

V1.8 directory structure is now considered **frozen**.

Future feature work should add functionality inside the canonical boundaries instead of recreating removed `engine/`, `lab/`, or transitional view registries.

Any future legacy exception must be accompanied by a dedicated compatibility test and an explicit removal plan.
