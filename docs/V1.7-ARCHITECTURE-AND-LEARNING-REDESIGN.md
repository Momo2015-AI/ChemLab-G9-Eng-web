# ChemLab-G9 V1.7 架构与学习内容重构升级方案

> 文档状态：规划基线
>
> 适用仓库：`ChemLab-G9-Eng-web`
>
> 原则：本仓库独立演进，不以其他 ChemLab 仓库作为运行时依赖。

---

## 1. 文档目标

本方案不是简单的目录整理，而是对 ChemLab-G9 进行一次 **“学习产品 + 学习引擎 + 内容系统 + 工程架构”四位一体升级**。

核心目标：

1. 让学生真正按照科学的认知规律学习，而不是“看页面 → 做题 → 看分数”。
2. 让课程、知识点、实验、题目、错题、掌握度和推荐形成可追踪的学习闭环。
3. 让 Engine 与 UI 解耦，避免 `ChemLabApp` 继续成为“大总管”。
4. 让所有学习内容具有明确的知识目标、前置知识、实验目标、评价标准和学习证据。
5. 保持原生 Web / ES Module / GitHub Pages 的轻量技术路线，不为了架构而引入复杂框架。
6. 为未来 AI 化学导师、多册课程、更多实验和更精细的学习分析预留稳定接口。

# 2. 当前版本审查结论

当前仓库已经具备较好的 V1.6 基础：

```text
engine/       应用引擎
core/         服务层
lab/          实验前端
Dashboard/    学情服务
modules/      模块化数据
content/      内容数据
schemas/      数据规范
.github/      CI/CD
```

已有能力包括：

- 学习流程
- 题库与分类
- 知识图谱
- 实验引擎
- 实验播放器
- 错题诊断模型
- 掌握度
- 推荐系统基础
- Dashboard
- GitHub Pages
- GitHub Actions

但当前存在明显的 **架构漂移**：

### 2.1 `ChemLabApp` 职责过多

当前 App 同时承担：

- 数据初始化
- localStorage
- 掌握度计算
- 答题评价
- Quiz 状态
- 实验状态
- 页面导航
- 页面渲染
- 深色模式
- 事件绑定

这会导致：

```text
功能越多
   ↓
App.js 越来越大
   ↓
模块之间耦合
   ↓
修改一个功能影响多个页面
```

### 2.2 Router 与页面状态存在双轨机制

当前既有 hash router，又有 `currentPage` 状态。

V1.7 应统一为：

```text
URL / Route
    ↓
Router
    ↓
Application State
    ↓
Page Controller
    ↓
View
```

### 2.3 `modules/` 与 `content/` 数据职责边界需要明确

未来必须确定唯一权威数据源。

建议：

```text
content/       = 教学内容
modules/       = 可复用领域模型 / 运行时配置
schemas/       = 数据契约
```

课程事实不应在两个目录重复维护。

### 2.4 CI 主要检查语法与 JSON

现有 CI 已能检查 JS 语法、JSON 和入口文件，但还不能验证：

- import 路径
- schema
- 数据引用完整性
- Router
- 核心学习流程
- 页面启动
- 关键用户流程

V1.7 必须把“能解析”升级到“能运行、能学习”。

# 5. App 重构原则

最终 `app.js` 只负责应用装配：

```javascript
startApp({
  router,
  state,
  learningEngine,
  assessmentEngine,
  experimentEngine,
  dashboard
});
```

不再负责：

- 题目评分算法
- 掌握度算法
- 实验步骤推进
- HTML 大量拼接
- 数据加载细节

目标：

```text
bootstrap
   ↓
compose services
   ↓
start application
```

# 6. 学习系统重新设计：从“页面学习”转向“认知学习”

这是 V1.7 最重要的升级。

ChemLab 不应只是一个电子教材，而应成为：

> **以学生理解化学概念为中心、以实验和问题解决为主要学习活动、以学习证据驱动反馈的学习系统。**

建议每个学习单元采用：

```text
1. 激活已有知识
        ↓
2. 提出问题
        ↓
3. 观察 / 实验
        ↓
4. 形成现象证据
        ↓
5. 建立微观解释
        ↓
6. 提炼化学概念
        ↓
7. 表示与符号化
        ↓
8. 基础练习
        ↓
9. 迁移问题
        ↓
10. 自我解释
        ↓
11. 掌握度更新
        ↓
12. 个性化下一步
```

这比简单的：

```text
知识 → 题目 → 分数
```

更符合科学学习过程。

# 7. 每个 Lesson 的标准结构

每节课建议固定为：

```text
Lesson
├── learning-goals
├── prerequisite
├── warm-up
├── core-concept
├── observation
├── experiment
├── microscopic-model
├── chemical-symbols
├── worked-example
├── guided-practice
├── independent-practice
├── transfer-problem
├── misconception-check
├── summary
└── next-step
```

### 7.1 学习目标必须可观察

不要写：

> 掌握氧气的性质。

应该写成：

> 能根据实验现象判断氧气具有支持燃烧的性质，并能用“实验现象 → 性质 → 结论”的结构解释自己的判断。

### 7.2 前置知识

每节课明确：

```json
"prerequisite": [
  "chemical-change",
  "observation-record"
]
```

如果学生前置知识不足，系统先给微型复习，而不是直接进入新课。

# 8. 化学内容的“三重表征”体系

初中化学尤其需要避免只讲宏观现象。

每一个核心概念建议同时建立：

```text
宏观层
实验现象 / 物质性质
       ↓
微观层
粒子、原子、分子、离子
       ↓
符号层
化学式、化学方程式、元素符号
```

例如学习某化学反应：

```text
看到什么？
   ↓
发生了什么？
   ↓
粒子如何变化？
   ↓
为什么？
   ↓
如何用化学方程式表示？
```

这是 ChemLab 与普通题库网站最应该拉开差异的地方。

# 9. 实验教学升级

实验不应只是“点击下一步”。

建议实验采用：

```text
实验任务
   ↓
预测
   ↓
选择仪器
   ↓
选择操作
   ↓
执行实验
   ↓
观察现象
   ↓
记录证据
   ↓
解释现象
   ↓
得出结论
   ↓
评价实验方案
```

学生应该能够犯“合理的错误”。

例如：

- 仪器选择错误
- 操作顺序错误
- 忽略安全条件
- 现象记录不完整
- 将现象与结论混淆
- 把“没有看到”误认为“没有发生”

系统记录错误类型，然后进入 Diagnosis Engine。

# 10. 实验内容标准

每个实验必须具备：

```text
实验目标
前置知识
仪器
药品 / 材料
安全要求
实验原理
实验步骤
可观察现象
关键变量
预期结论
常见错误
错误后果
改进方案
```

尤其增加：

### 变量意识

让学生理解：

```text
改变什么？
保持什么不变？
观察什么？
为什么这样设计？
```

逐步培养科学探究能力，而不仅是记步骤。

# 11. 题目系统升级

题目不再只保存：

```text
题干 + 答案
```

而应保存：

```text
题目
├── knowledge
├── prerequisite
├── cognitive-level
├── difficulty
├── representation
├── error-types
├── explanation
├── hints
├── distractor-diagnosis
├── source
└── transfer-target
```

建议认知层级：

```text
Recall       记忆
Understand   理解
Apply        应用
Analyze      分析
Evaluate     评价
Create       设计 / 探究
```

初中化学不需要机械追求高阶标签数量，而应保证：

> 基础理解 → 规范应用 → 情境迁移 → 简单探究

逐步递进。

---

# 12. 错题诊断系统升级

不要只记录：

```text
答错了
```

应该判断：

```text
为什么错？
```

建议错误分类：

```text
概念错误
性质混淆
现象识别错误
因果关系错误
符号错误
方程式错误
计算错误
单位错误
实验操作错误
审题错误
推理链断裂
知识迁移失败
```

题目的干扰项应该与错误类型绑定。

例如：

```text
选择 B
   ↓
Diagnosis
   ↓
“将实验现象与物质性质混淆”
   ↓
Mini Lesson
   ↓
相似题
   ↓
迁移题
```

这样“错题”才真正成为学习数据。

---

# 13. Mastery 掌握度不要只用正确率

当前简单的：

```text
correct / attempts
```

不足以表示真实掌握度。

建议至少考虑：

```text
正确率
+ 最近表现
+ 难度
+ 题型覆盖
+ 独立完成程度
+ 提示依赖
+ 知识前置状态
+ 实验表现
```

最终形成：

```text
Mastery Score

Conceptual
Procedural
Application
Transfer
Experiment
```

例如：

```text
氧气性质

概念理解    86%
实验操作    72%
现象判断    91%
迁移应用    64%

总体掌握度  78%
```

这样 Dashboard 才真正有教育意义。

---

# 14. 推荐系统升级

推荐系统不应该简单地：

> 做错题 → 再来一道题。

建议采用：

```text
错误诊断
   ↓
判断缺失能力
   ↓
查找前置知识
   ↓
选择最小补救单元
   ↓
微练习
   ↓
原知识点复测
   ↓
迁移题
```

形成“最小学习闭环”。

推荐优先级：

1. 前置知识缺失
2. 核心概念误解
3. 高频错误
4. 当前课程目标
5. 迁移能力
6. 拓展内容

# 15. AI 化学导师的正确位置

AI 不应直接替代教学内容。

推荐架构：

```text
Student
   ↓
Learning Engine
   ↓
Diagnosis
   ↓
AI Tutor
   ↓
受控知识库 / 当前课程上下文
   ↓
Hint / Explanation / Socratic Question
```

AI 导师主要负责：

- 追问
- 提示
- 换一种解释
- 检查学生自己的解释
- 引导实验推理
- 分析错误原因

不应该默认直接给答案。

建议支持：

```text
Hint 1：提醒观察
Hint 2：指出相关概念
Hint 3：给出推理方向
Hint 4：展示类似例题
```

只有在合理学习流程后才提供完整解释。

# 16. Dashboard 重新定位

Dashboard 不应该只是展示数字。

首页应该回答学生三个问题：

### 我现在学到哪里？

```text
课程进度
知识掌握
实验完成
```

### 我哪里还不明白？

```text
薄弱知识点
高频错误
未掌握前置知识
```

### 我下一步应该做什么？

```text
今日任务
推荐复习
推荐实验
推荐练习
```

最终首页可以形成：

```text
今天继续学习
      ↓
当前课程
      ↓
我的薄弱点
      ↓
推荐任务
      ↓
学习成就
```

而不是单纯 KPI 面板。

# 17. 内容生产标准

未来所有课程内容必须经过 Content QA。

每节课至少检查：

### 科学性

- 概念准确
- 化学事实准确
- 方程式准确
- 实验现象符合实际
- 因果关系严谨

### 教学性

- 有明确目标
- 前置知识合理
- 难度递进
- 不跳跃
- 有错误诊断
- 有迁移任务

### 学生体验

- 单次学习任务不过长
- 手机 / iPad 可读
- 重要信息视觉层级明确
- 操作反馈及时
- 不依赖大段文字

### 实验安全

- 明确安全边界
- 不鼓励真实危险操作
- 虚拟实验与现实实验明确区分

# 18. 内容粒度建议

不要采用“一个 Day = 一大页”的模式。

建议：

```text
Chapter
  ↓
Unit
  ↓
Lesson
  ↓
Learning Activity
  ↓
Knowledge Point
```

例如：

```text
Lesson 03
│
├── Activity 1 观察
├── Activity 2 实验
├── Activity 3 微观解释
├── Activity 4 符号表示
├── Activity 5 基础练习
├── Activity 6 迁移
└── Activity 7 自测
```

这样学习引擎才能精确知道学生卡在哪一步。

# 20. ID 体系

V1.7 必须建立稳定 ID。

例如：

```text
chapter-air

knowledge-oxygen-property
experiment-oxygen-test-001
question-q0001
```

# 24. 最终产品定位

ChemLab-G9 V1.7 不应继续沿着“更漂亮的化学网页”发展。

真正应该建设的是：

```text
              ChemLab Learning OS

                    学生
                     │
                     ↓
              学习目标与任务
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
        课程        实验        练习
          │          │          │
          └──────────┼──────────┘
                     ↓
                 学习证据
                     ↓
              Diagnosis Engine
                     ↓
               Mastery Model
                     ↓
          ┌──────────┴──────────┐
          ↓                     ↓
      Review Path           Next Task
          │                     │
          └──────────┬──────────┘
                     ↓
                Student Growth
```

核心理念：

> **不是让学生完成更多页面，而是让系统越来越清楚学生真正理解了什么、哪里没有理解、为什么没有理解，以及下一步最值得学习什么。**

# 25. V1.7 开发优先级

最高优先级：

1. 学习数据模型
2. Lesson 内容标准
3. Knowledge 数据模型
4. App 解耦
5. Learning Flow
6. Diagnosis
7. Mastery
8. 实验学习流程
9. Dashboard
10. AI Tutor

暂缓：

- 大规模视觉特效
- 复杂动画
- 与学习无关的 UI 装饰
- 过早引入前端框架
- 复杂后端基础设施

**先把“学生怎么学”设计正确，再把“系统怎么运行”设计稳定，最后才增加 AI 和视觉能力。**
