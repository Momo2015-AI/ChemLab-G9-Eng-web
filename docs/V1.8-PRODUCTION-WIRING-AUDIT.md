# V1.8 Production Wiring Audit

## Scope

This audit checks the real production path rather than relying only on unit-level contracts.

Canonical runtime:

`index.html → app/bootstrap.js → app/application.js → controllers/services → views`

## Findings and resolution

| Item | Finding | Resolution |
|---|---|---|
| Question registration | The diagnosis question map existed but production registration was not guaranteed by the controller path. | `ContentService.load()` now registers every loaded question with normalized knowledge/error metadata. |
| Assessment diagnosis | `AssessmentController.answer()` previously updated mastery but did not persist diagnosis/remediation. | `answer()` now calls the canonical diagnosis adapter and sends incorrect diagnoses to `LearningController.getRemediationPlan()`. |
| Remediation persistence | The remediation engine existed but production needed an explicit catalog and controller wiring. | Bootstrap derives a catalog from canonical content and the assessment flow persists the generated plan. |
| Knowledge graph P0 | Loader still requested the legacy graph path, allowing legacy `from/to` data to reach the canonical engine. | Loader now prefers `content/knowledge/knowledge-graph.json`; ContentService also normalizes `from/to` to `source/target`. |
| Diagnosis/content contract | Diagnosis depended on a global map while question content already carries knowledge metadata. | The map remains a canonical adapter, but registration is owned by ContentService rather than UI/controller code. |
| Experiment multi-knowledge | Experiment controller recorded evidence for one knowledge id only. | Experiment sessions now preserve all `knowledge`/`knowledgeIds`, and evidence is recorded for every target. |
| Experiment diagnosis | Experiment evidence did not participate in the same production diagnosis/remediation path. | Experiment observations now produce the canonical diagnosis contract and can create remediation. |
| Experiment schema | Schema used `name` while canonical experiment content uses `title` and `knowledge`. | Schema now reflects the canonical production fields while retaining `name` as a compatibility field. |
| Remediation catalog ownership | Catalog ownership was implicit and the composition root defaulted to `{}`. | Added `core/diagnosis/remediation-catalog.js`, derived from loaded knowledge nodes and questions. |
| Legacy runtime | Legacy files may remain for compatibility, but production entry must not depend on them. | Existing production-runtime gate remains in place; obsolete graph runtime layers were removed earlier. |

## Production invariant

The intended learning loop is now:

```text
Question / Experiment
        ↓
Learning Evidence
        ↓
Canonical Diagnosis
        ↓
Remediation Plan
        ↓
Targeted Recheck
        ↓
Mastery Update
        ↓
Dashboard / Recommendation
```

## Verification

`tests/production-wiring-v18.test.mjs` locks the following contracts:

- legacy graph edge normalization
- question registration at the content boundary
- assessment diagnosis → remediation
- multi-knowledge experiment evidence
- data-derived remediation catalog

The final release gate remains `npm test` with zero failures, followed by GitHub Actions and GitHub Pages deployment from `main`.
