# V1.7 Content Pipeline

## Canonical boundary

```text
index.html
  ↓
app/bootstrap.js
  ↓
app/application.js
  ↓
app/content-service.js
  ↓
app/content-loader.js
  ↓
manifest + lesson/question/knowledge JSON
  ↓
canonical-knowledge-engine.js
```

## Responsibilities

- `app/content-service.js` is the application-facing content API.
- `app/content-loader.js` owns manifest-driven JSON loading and deployment-base resolution.
- `core/knowledge-graph/canonical-knowledge-engine.js` owns graph traversal and graph queries.
- Controllers and views consume `ContentService`; they do not load content files directly.
- `engine/content-loader.js` is deprecated and is now only a compatibility re-export to prevent a second implementation from drifting.

## Migration rule

No new production import may target `engine/content-loader.js`. Existing external/legacy imports can continue through the shim until the next breaking cleanup window, at which point the shim can be removed safely after a repository-wide import audit.

## Data flow

`manifest.json` determines the lesson set. Question-bank and topic-bank data are indexed by the loader. Knowledge-graph data is passed once into the canonical engine owned by `ContentService`.
