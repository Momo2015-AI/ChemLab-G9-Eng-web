# ChemLab-G9-Eng-web 开发计划 (Development Roadmap)

**Status:** CANONICAL / MANDATORY — 所有向本仓库提交内容或代码的贡献者（包括人类与 AI agent）都必须遵循本文档。
**Version:** 1.0
**Established:** 2026-08-25
**依据:** 本文档基于对仓库当前状态的实际审计（代码、测试、审计脚本运行结果），不是愿景性规划——每一条结论都能通过 `npm test` / `npm run audit:content` 复现。

## 0. 如何使用本文档

- 开新课之前，先看第 2 节确认这是不是当前该做的单元。
- 写代码 / 加内容之前，先看第 3 节的强制质量门禁——这些不是建议，是 `npm test` 会拦下来的硬性要求。
- 遇到"审计脚本说 PASS 但你怀疑内容有问题"的情况，直接看第 1.1 节——这类情况已经发生过，处理方式是写下来的，不用重新发明。
- 本文档每次发现新的系统性问题（不是单个 bug，是"这类问题会反复出现"的问题）都要更新，同时必须补一条自动化测试把它钉死，而不是只在这里写一段话提醒大家小心。

## 1. 架构方向

### 1.1 最高优先级：审计脚本本身不可信,已经骗过我们三次

这是本次审计最重要的发现，必须放在最前面。截至目前，`content-integrity-v19.mjs` / `content-lesson-audit-v19.mjs` 至少三次因为"内容用了脚本没预料到的合法数据形状"而**要么直接崩溃、要么静默漏计、但依然报告 Gate PASS**：

1. `-transfer.json` 用 `transfer.scenarios` 而不是 `questions[]`（已修复，2026-08-21）
2. `-diagnostic.json` 用 `questions` 而不是 `diagnostics` 键（脚本 fallback 直接兜底成整个原始对象，导致 `for...of` 崩溃；已修复，2026-08-25）
3. `-mastery.json` 用全新的 `{dimensions, criteria, items}` 多维度结构，运行时引擎完全不认识，Gate 依然显示 PASS，5 门课的掌握度检测环节实际上是坏的（已修复，2026-08-25）

**根本教训：`npm run audit:content` 报 PASS ≠ 内容真的能在运行时工作。** 脚本用的是"尽力而为"的字段读取（`a?.b || a`），这种写法在遇到未预料的新形状时会静默失败而不是报错。已经把已知的几种 fallback 分支改成了显式 `Array.isArray()` 判断+空数组兜底（不会再崩溃），并且补了 `tests/content-namespace-integrity.test.mjs` 直接断言 mastery/diagnostic 文件的可加载性，独立于审计脚本本身。

**要求**：以后任何人给 `-mastery.json` / `-diagnostic.json` / `-transfer.json` / `-practice.json` 设计新的数据形状（哪怕只是想让内容更丰富），**必须先在 `app/content-loader.js` 里确认运行时读得懂**，而不是先写内容再指望审计脚本能发现问题——审计脚本是安全网，不是设计规范的来源。真正的规范是 `app/content-loader.js` 里 `loadMastery` / `loadGuidedLearning` 等函数实际读取的字段。

### 1.2 Source Registry 的 S0 签字——连续四轮审查都还是 PARTIAL

从 5 门课到现在 21 门课，这个状态一直没变。这是本仓库唯一一个**只能由人完成、不能自动化**的阻塞项。工作量很小（核对来源、签字确认），但拖得越久，需要回溯核对的课就越多。**这是当前排在第一位的非代码待办事项，建议项目所有者本周内处理**，不要等到课程量再翻一倍。

### 1.3 知识图谱设计需要一次真正的教研评审

2026-08-25 已经补齐了 u02/u04/u05 的专属知识节点（不再用"最接近的节点"顶），全仓库验证零悬空引用。但这些节点的前置关系（`prerequisiteIds`）和粒度划分是我（AI）按人教版课题结构推断设计的，**没有真人教研核对过**。建议找熟悉这几个单元教学设计的人专门评审一次，尤其是像 `chemical-formula-writing` 这种合并了多个误解类型的节点，粒度是否合适可以再讨论。

### 1.4 Mastery 题库厚度不均——一个新出现的质量问题

u01-u13 各课的 mastery 题池普遍在 20-27 题（`threshold: 0.95, minCorrect: 20` 左右），但 u06 五门新课的 mastery 题池只有 8 题（且这 8 题目前是从课程正文里复用的旧题，不是"unseen-transfer"设计要求的全新题——2026-08-25 已重新分配 ID 避免了 ID 冲突，但没有解决"不是真正未见过的题"这个更深的设计问题）。**这是一项具体的内容负债，见第 2.4 节。**

### 1.5 次优先级（不阻塞当前工作，按需推进）

- 浏览器端到端测试仍然缺失，20+ 门课之后 UI 复杂度已经上了一个台阶，建议排上日程，不必再拖
- `day` / `sequenceNumber` / `displayOrder` 三个排序字段并存，只有 `displayOrder` 真正生效，建议清理
- 确认 `tests/*.test.mjs` 是否接入了 CI（GitHub Actions），如果没有，本地不跑测试就推送仍然会撞车或漏检

## 2. 课程结构方向

### 2.1 当前真实覆盖（2026-08-25 审计）

| 单元 | 课时数 | 覆盖内容 |
|---|---:|---|
| u01 走进化学世界 | 3 | 变化与性质 / 科学方法 / 实验安全 —— **收口** |
| u02 我们周围的空气 | 3 | 氧气性质 / 两种制取方法 —— **收口** |
| u03 物质构成的奥秘 | 4 | 分子原子 / 原子结构 / 离子键 / 元素 —— **收口** |
| u04 自然界的水 | 4 | 水的组成 / 净化 / 资源保护 / 化学式与化合价（上）—— **收口** |
| u05 质量守恒定律 | 1 | 质量守恒与化学计算 —— 只有 1 课，人教版这个单元通常还包含"化学方程式的书写与配平"独立课时，**未收口** |
| u06 碳和碳的氧化物 | 5 | 碳单质 / 碳化学性质 / CO2制取 / CO2性质 / CO —— **收口**，但见 2.4 的 mastery 质量问题 |
| u10 常见的酸和碱 | 1 | 只有"酸入门" —— **远未收口**，碱、pH、中和反应都没做 |

未开始：u07（燃料及其利用）、u08（金属和金属材料）、u09（溶液）、u11（常见的盐）、u12（化学与生活）。

### 2.2 下一步优先级（按顺序）

1. **补齐 u05 的化学方程式书写与配平课时**——目前只有"质量守恒定律与化学计算"1 课，人教版这个单元通常需要专门一课讲配平方法（最小公倍数法等），这是後续所有化学计算题的基础，优先级最高。
2. **补齐 u10（酸和碱）**——"酸入门"已经开了头快两周了，一直没有后续。趁热补上碱的性质、酸碱指示剂与 pH、中和反应，让这个单元真正收口。**这一项被反复提出但一直没有推进，建议本轮优先处理，不要再往后拖。**
3. **u07/u08/u09 按人教版顺序推进**——燃料及其利用、金属和金属材料、溶液，这三个单元是上册收尾+下册开篇的核心内容，u06（碳）已经做完，顺着课标顺序走是最低风险的路径。
4. **u11/u12 留到最后**——常见的盐、化学与生活，这两个依赖前面所有单元的知识，且目前完全没开始，不用急。

### 2.3 不要再出现的模式：单元内部顺序跳跃

u05 目前只有 1 课就直接标记为"收口"是不准确的（见 2.1），这是因为课程生产没有对照 `docs/CURRICULUM-MAP-G9.md` 里每个单元实际包含几个课题就直接往下一个单元推进。**要求：产完一个单元的课之前，先对照 `CURRICULUM-MAP-G9.md`（如果没写清楚这个单元该有几课，先去确认人教版教材目录），确认这个单元的课题是不是真的都覆盖了，再标记这个单元"收口"、开始下一个单元。**

### 2.4 内容负债清单（明确记录，不要假装不存在）

- **u06 五门课的 mastery 题池需要重新出题**：目前 8 题里全部复用自课程正文的概念检测题，不符合"unseen-transfer"的设计原则（学生应该被未见过的题检验，而不是重考刚做过的题）。需要新出约 15-20 道题，参照 u01-u13 的题量标准。这个工作量不小，建议作为独立任务排期，不要顺手糊弄。
- **u05 只有 1 课**，人教版这个单元的完整范围需要与 u10 补课一起排进本轮计划。

## 3. 质量门禁（强制，所有贡献者必须遵守）

这一节是对 `docs/COURSE-DEVELOPMENT-STANDARD.md` 第 16 节（命名空间与 ID 分配）的补充，聚焦在"提交前必须做什么"，不是重复内容。

### 3.1 提交前必须跑、且必须全绿

```bash
npm test              # 186 项测试（随内容增长会变多），必须 0 fail
npm run audit:content # 两个审计脚本都要跑完不崩溃，Gate 必须是 PASS
```

**只看 Gate 是不是 PASS 不够**——如第 1.1 节所述，Gate 曾经在真实问题存在的情况下依然显示 PASS。如果你新增/修改了 `-mastery.json`、`-diagnostic.json`、`-transfer.json`，额外确认：

```bash
node --test tests/content-namespace-integrity.test.mjs
```

这个文件里专门有三个测试断言这三类文件的运行时可加载性，是本次事故后新加的安全网。

### 3.2 新数据形状先过"运行时读得懂"这一关

在给任何 `-mastery.json` / `-diagnostic.json` / `-guided-learning.json` / `-experiment.json` / `-transfer.json` / `-practice.json` 设计新字段结构之前：

1. 打开 `app/content-loader.js`，找到对应的 `load*` 函数，确认它实际读取的字段路径。
2. 如果你的新结构和现有字段路径不一致，要么改成一致，要么同时提交 `app/content-loader.js` 的适配改动——**两者必须在同一个 PR/commit 里，不能只改内容不改运行时**。
3. 如果新结构代表一种更好的设计（比如 u06 那种多维度 mastery 评分），要先确认这是不是整个项目要迁移的新标准；如果只是单个贡献者的即兴设计，不要单独在一批课上用，这会造成运行时不兼容且难以发现（本次事故就是这么发生的）。

### 3.3 硬编码列表 = 禁止（Section 16.4 的重申与扩展）

任何测试、脚本、文档如果需要"当前课程列表""误解总数""图谱节点数"这类事实，必须从真实数据源（`content/curriculum/lesson-manifest.js`、`content/misconceptions/canonical-misconceptions.js`、`content/knowledge/knowledge-graph.json`）动态读取。**精确值断言（`assert.equal(x, 具体数字)`）只允许用在数据源本身不会随内容增长而改变的地方**；如果这个数字会随着别人加课程而变化，用下限检查（`assert.ok(x >= N)`）或直接从数据源对比，不要写死一个当前时刻的快照值。

### 3.4 单元收口前必须对照课程地图

见第 2.3 节。产完一个单元的最后一课，标记这个单元状态之前，先确认这个单元在 `docs/CURRICULUM-MAP-G9.md` 里定义的完整课题范围是不是真的都覆盖了。

## 4. 本文档的维护规则

- 每次审查发现一类会反复出现的系统性问题，**同时**做三件事：写自动化测试钉死它、在这里补一条记录、如果涉及流程规范就同步更新 `COURSE-DEVELOPMENT-STANDARD.md`。只做其中一件事（比如只在这里写一段提醒，但不加测试）不算完成。
- 第 2.1 节的课程覆盖表每次有单元收口/开新单元时更新；不需要每次加一课就更新，但每个单元状态变化必须更新。
- 如果某一条规则被证明是错的或者不再适用，直接删除或改写，不要无限累加规则导致后来者读不完——本文档的目标是"读完能照着做"，不是"记录所有历史"。
