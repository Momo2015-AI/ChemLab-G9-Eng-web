# V1.7 Diagnosis Architecture

## Purpose

Diagnosis is a domain service that converts assessment and experiment evidence into one stable learning diagnosis contract. Controllers and views do not own diagnosis policy.

## Canonical flow

```text
Assessment / Experiment evidence
            ↓
   diagnosis-engine.js
            ↓
     Diagnosis result
            ↓
 remediation-engine.js
            ↓
 review / practice / recheck
            ↓
 targeted assessment + mastery evidence
```

## Canonical diagnosis contract

### Correct

```js
{
  status: 'correct',
  recommendation: 'continue'
}
```

Experiment evidence also carries `knowledge` and `source: 'experiment'` so downstream remediation can retain the target context.

### Incorrect

```js
{
  status: 'incorrect',
  knowledge: ['knowledge-id'],
  possibleErrors: ['error description'],
  recommendation: 'review-and-practice'
}
```

### Unknown

```js
{
  status: 'unknown',
  message: '...'
}
```

Unknown evidence must not fabricate remediation.

## Module responsibilities

- `core/diagnosis/diagnosis-engine.js` — **canonical policy engine**. Owns assessment and experiment diagnosis entry points.
- `core/diagnosis/question-knowledge-map.js` — question-to-knowledge/error mapping used by assessment diagnosis.
- `core/diagnosis/learning-diagnosis.js` — compatibility adapter only. It re-exports the canonical engine API and contains no diagnosis policy.
- `core/diagnosis/remediation-engine.js` — converts diagnosis into deterministic review/practice/recheck or transfer actions. It does not diagnose.
- `core/diagnosis/error-type-model.js` — reusable error vocabulary/record model. It is intentionally separate from the diagnosis decision path until typed error records are adopted end-to-end.

## Architectural rules

1. Do not implement diagnosis logic in controllers or views.
2. Do not create a second assessment/experiment diagnosis algorithm.
3. Remediation consumes diagnosis; it does not infer correctness itself.
4. Targeted recheck consumes diagnosed knowledge IDs and feeds new evidence back through the normal assessment/mastery path.
5. Changes to the diagnosis contract require updates to the diagnosis tests and remediation tests together.
