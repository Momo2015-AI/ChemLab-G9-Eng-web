# V1.7 KnowledgeEngine Consolidation

## Why two engines appeared

The duplicate engines came from architectural evolution rather than a deliberate product requirement. The older `engine/knowledge-engine.js` grew inside the V1.5/V1.6 application runtime and models relations as fields embedded inside each node. Later, the `core/knowledge-graph/knowledge-engine.js` was introduced as a domain-oriented graph implementation with explicit `nodes` and `relations` collections. Because the refactor added the new core layer before all legacy consumers were migrated, both implementations remained in the repository.

This is a classic parallel-migration problem: a new abstraction was introduced without first establishing a single canonical data model and without completing consumer migration before retaining the legacy module.

## Canonical decision

V1.7 adopts the explicit graph model:

- nodes are identified by stable IDs;
- relations are first-class records with `source`, `target`, and `type`;
- graph queries belong to the knowledge domain;
- legacy node-embedded relation fields are supported temporarily as a compatibility input only.

The canonical implementation is `core/knowledge-graph/canonical-knowledge-engine.js` during the migration gate.

## Migration rule

No new feature may import `engine/knowledge-engine.js`. New code must use the canonical engine. Existing consumers will be migrated and tested before the legacy file is removed.

## Why not delete the old engine immediately?

The repository currently contains V1.5/V1.6 consumers and mixed content formats. Deleting the old implementation before tracing those consumers would create silent regressions. The compatibility query layer therefore provides a controlled bridge while callers migrate.

## Next actions

1. Inventory all imports/usages of both engines.
2. Migrate callers to the canonical engine.
3. Normalize knowledge graph content to explicit relations.
4. Add graph traversal/query tests.
5. Delete `engine/knowledge-engine.js` after the usage audit is zero.
6. Rename `canonical-knowledge-engine.js` to `knowledge-engine.js` once the old path is gone.
