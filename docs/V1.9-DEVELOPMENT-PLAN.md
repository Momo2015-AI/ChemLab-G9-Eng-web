# ChemLab-G9 V1.9 Development Plan

**Baseline:** V1.8 Architecture + Directory Freeze
**Branch:** `main`
**Test baseline:** 66 / 66 GREEN

## 1. V1.9 objective

V1.9 is a product-capability phase, not another foundational rewrite.

The goal is to turn the stable evidence/diagnosis/mastery architecture into a coherent student-facing learning experience:

```text
Learning Center
  ↓
Knowledge Learning
  ↓
Interactive Experiment
  ↓
Assessment
  ↓
Evidence
  ↓
Diagnosis
  ↓
Personalized Remediation
  ↓
Targeted Recheck
  ↓
Mastery / Dashboard
  ↓
Transfer / Next Task
```

## 2. Phase 1 — Learning Center UX

### Goal
Create the primary student learning surface on top of the existing canonical services.

### Deliverables

- learning-center route/page
- lesson list and lesson detail
- knowledge-point entry
- prerequisite indication from the canonical knowledge graph
- progress and mastery summary
- clear next-action recommendation
- responsive/iPad-friendly layout

### Acceptance

- no direct content loading from views
- all content comes through `ContentService`
- completion remains separate from mastery
- existing tests remain GREEN

## 3. Phase 2 — Lesson content system

### Goal
Turn canonical lesson data into an actual teaching sequence.

### Deliverables

- lesson schema/data validation
- concept explanation blocks
- worked examples
- misconception hints
- experiment links
- assessment links
- transfer tasks
- previous/next lesson navigation

### Acceptance

Every lesson has stable:

```text
lessonId
knowledgeId(s)
learning objectives
content blocks
assessment links
experiment links
```

## 4. Phase 3 — Assessment UX 2.0

### Goal
Expose the already-working AssessmentController through a usable student interface.

### Deliverables

- question renderer
- answer interaction
- immediate/controlled feedback
- evidence capture
- diagnosis display
- retry/recheck entry
- question progress indicator

### Acceptance

The UI must drive the existing controller rather than reproduce assessment logic.

## 5. Phase 4 — Diagnosis + Remediation UX 2.0

### Goal
Make the diagnosis result actionable for students.

### Deliverables

- diagnosis explanation
- identified knowledge target
- misconception/error explanation
- remediation plan
- review activity
- targeted practice
- targeted recheck

### Acceptance

```text
wrong answer
→ diagnosis
→ remediation
→ recheck
```

must be visible and executable in the UI.

## 6. Phase 5 — Virtual Experiment UX 2.0

### Goal
Connect experiments to the learning loop rather than treating them as isolated simulations.

### Deliverables

- experiment selection
- equipment/instrument presentation
- step-by-step procedure
- observation interaction
- validation feedback
- multi-knowledge evidence
- experiment completion state
- links to remediation/recheck when appropriate

### Acceptance

Experiment evidence must use the same canonical evidence/mastery/diagnosis contracts as assessment evidence.

## 7. Phase 6 — Dashboard 2.0

### Goal
Build a student dashboard around learning decisions rather than raw statistics.

### Deliverables

- completion progress
- mastery by knowledge point
- recent evidence
- diagnosis history
- active remediation
- recheck status
- recommended next task

### Acceptance

Dashboard remains a read model and never mutates canonical state directly.

## 8. Phase 7 — Transfer and adaptive next-task loop

### Goal
Move from remediation to genuine transfer learning.

### Deliverables

- transfer question/task model
- prerequisite-aware task selection
- mastery threshold handling
- next-task recommendation
- evidence feedback into mastery

### Acceptance

The system should answer:

> “What is the most valuable next learning action for this student?”

without creating a second recommendation engine.

## 9. Phase 8 — End-to-end production validation

### Goal
Validate the complete student journey in a real browser.

### Scenario

```text
open platform
→ select lesson
→ learn concept
→ perform experiment
→ answer question
→ produce incorrect evidence
→ receive diagnosis
→ execute remediation
→ targeted recheck
→ mastery changes
→ dashboard updates
→ next task
```

### Deliverables

- browser smoke tests
- production content loading verification
- GitHub Pages verification
- error-state verification
- mobile/iPad layout verification
- release checklist

## 10. Cross-phase engineering rules

Every feature follows:

```text
Design
→ implementation
→ tests
→ npm test GREEN
→ Build Check GREEN
→ docs update
→ commit on main
→ Pages deployment
```

### Never do

- create a second state store
- create a second knowledge graph
- duplicate mastery calculations
- duplicate diagnosis logic in controllers/views
- bypass `ContentService`
- reintroduce deleted legacy runtime
- introduce untested content contracts

## 11. V1.9 completion criteria

V1.9 is complete only when:

- Learning Center is usable
- lesson learning is usable
- assessment is usable
- diagnosis is understandable
- remediation is executable
- recheck is executable
- experiment evidence reaches mastery/diagnosis
- dashboard reflects canonical state
- transfer/next-task flow works
- complete browser journey works
- automated tests remain GREEN
- Pages deployment is GREEN

## 12. Priority order

```text
P0  Learning Center shell + lesson UX
P0  Assessment UX
P0  Diagnosis/Remediation UX
P1  Experiment UX
P1  Dashboard 2.0
P1  Transfer / next-task loop
P2  visual polish
P2  performance optimization
P2  additional analytics
```

The priority is deliberately weighted toward the student learning loop, not decorative features.
