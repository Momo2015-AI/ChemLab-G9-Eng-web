# V1.7 Phase 1.9 — Smoke Test & Legacy Runtime Gate

## Purpose

Establish a repeatable minimum verification layer before removing the legacy application runtime.

## Checks

- Hash parsing and route fallback.
- Application content-service module can be imported.
- Route parameters remain available to controllers.
- Legacy runtime is not deleted until browser-level behavior is verified.

## Manual browser checklist

1. Open the site with an empty hash.
2. Navigate to a lesson route.
3. Load a lesson from the content service.
4. Start a quiz and submit one option.
5. Complete a quiz and inspect the result state.
6. Start an experiment and record an observation.
7. Complete the experiment.
8. Open Dashboard and Knowledge Graph.
9. Refresh the page and confirm progress persistence.

## Gate

`engine/app.js` remains in place until all items above pass against the production entry point. A structural refactor is not considered complete merely because the modules compile or import successfully.

## Next

Once browser verification is green, migrate the production entry point fully to the composition root, remove duplicate routing/rendering responsibilities, and only then delete obsolete legacy code.
