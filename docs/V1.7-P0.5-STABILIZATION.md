# V1.7 P0.5 — Runtime Stabilization

## Objective

Finish the runtime-side refactor before migrating additional educational content.

## Rules

1. `MasteryEngine` is the only authority allowed to calculate mastery.
2. `ChemLabApp` must not calculate `correct / attempts` mastery directly.
3. `ChemLabApp` must not become the long-term owner of persistence, routing, content loading, assessment, or rendering.
4. `ContentService` is the application-facing content boundary.
5. Legacy `modules/` data is not deleted until canonical content is validated and all consumers have migrated.

## Extraction order

```text
AppState / persistence
        ↓
Router
        ↓
ContentService
        ↓
Assessment + Learning Flow
        ↓
Experiment Flow
        ↓
Dashboard / Diagnosis
        ↓
View rendering
        ↓
Legacy app.js removal
```

## Exit criteria

- No duplicate mastery calculation remains outside `MasteryEngine`.
- Core mastery, diagnosis and graph-query tests run in CI.
- App state persistence is isolated behind `app/state.js`.
- Content loading is isolated behind `app/content-service.js`.
- No new business logic is added to `engine/app.js`.
- `innerHTML` rendering is either escaped or replaced with DOM-safe APIs.

Only after these gates pass should V1.7 proceed with large-scale content migration.
