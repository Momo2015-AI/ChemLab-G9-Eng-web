# ChemLab-G9-Eng-web V1.9 Content Audit

> Audit scope: content provenance → scientific accuracy → Grade 9 suitability → question quality → knowledge relationships.
>
> Audit status: **Phase 0 complete; remediation required before content expansion is considered production-ready.**

## 1. Audit basis

The primary curriculum reference is the **2022 edition of the Compulsory Education Chemistry Curriculum Standard** issued by the Ministry of Education. The 2022 curriculum reform explicitly emphasizes student cognitive development, connection with life and society, scientific practice, core competencies, and relationships within and across subjects.

Official references:

- Ministry of Education: https://hudong.moe.gov.cn/srcsite/A26/s8001/202204/t20220420_619921.html
- 2024 national textbook catalogue: https://www.moe.gov.cn/srcsite/A26/s8001/202408/W020250418502592948423.pdf

The current repository declares itself as a Grade 9 chemistry learning platform and its README defines the learning loop as learning → experiment → assessment → evidence → diagnosis → remediation → recheck → transfer. This is a sound product direction, but the content layer must become evidence-based and auditable before the loop can be trusted.

## 2. Executive findings

| Dimension | Status | Finding | Priority |
|---|---|---|---|
| Content provenance | ⚠️ Incomplete | Content has no consistently enforced source/provenance metadata. The question schema has an optional `source`, but no repository-wide source registry or verification state. | P0 |
| Scientific accuracy | ⚠️ Partially auditable | Several experiment records are plausible and include safety notes, but there is no automated scientific fact/equation validation layer. | P0 |
| Grade 9 suitability | ⚠️ Mixed | The curriculum map correctly targets junior-high chemistry, but currently labels all units as `planned` while content already exists for lower-secondary topics. This weakens scope control. | P1 |
| Question quality | ❌ Not production-ready | `content/questions` currently contains only `question-schema-v2.js`; the knowledge graph and experiment records reference question IDs that are not backed by question content in this repository. | P0 |
| Knowledge relationships | ⚠️ Strong foundation, weak integrity controls | A large canonical knowledge graph exists, but cross-reference integrity is not currently enforced by tests. | P0 |
| Content governance | ⚠️ Missing | No explicit editorial workflow exists for draft → reviewed → verified → published content. | P0 |

## 3. Repository evidence

### 3.1 Curriculum

`content/curriculum/g9-course-map.js` defines Grade 9 chemistry across two semesters and uses the expected major topic structure: air, matter structure, water, chemical equations, carbon oxides, fuels, metals, solutions, acids/bases, salts/fertilizers, and chemistry in life. However, all units are currently marked `planned`, even though the repository already contains lower- and upper-semester knowledge/experiment records.

**Action:** change curriculum status from a planning-only flag to a real content lifecycle state, for example:

```text
planned → drafting → reviewed → verified → published
```

### 3.2 Experiments

The repository contains experiment JSON records covering oxygen preparation, acid/metal and acid/metal-oxide reactions, rust, ion tests, gas preparation, fertilizer and comprehensive activities.

The oxygen experiment contains a reasonable safety-critical ordering note: remove the delivery tube before stopping heating. This is an important example of content that should remain tied to the experiment record and not be reduced to decorative UI text.

However, experiment records currently mix fields such as `chapter`, `module`, `day`, `knowledge`, and `questions` without a single canonical contract. This makes automated auditing harder.

**Action:** normalize experiment metadata and require:

- `knowledgeIds`
- `questionIds`
- `learningObjectives`
- `phenomena`
- `equation` where applicable
- `safety`
- `source`
- `reviewStatus`

### 3.3 Questions

The repository currently defines a good V2.1 question contract requiring:

- id
- type
- stem
- answer
- explanation
- knowledgeIds
- difficulty
- cognitiveLevel

It also supports experiment IDs, prerequisite IDs, misconception IDs, remediation, tags and source metadata.

This is architecturally correct, but the actual `content/questions` directory currently contains only `question-schema-v2.js`. Therefore the assessment layer must **not** be treated as content-complete.

The knowledge graph references IDs such as `q-fund-001` and experiment records reference IDs such as `q-acid-007` and `q-acid-008`, but corresponding question records are not currently present under the canonical question directory.

**Action:** classify all currently referenced-but-missing question IDs as `orphan references` and block production assessment claims until resolved.

### 3.4 Knowledge graph

`content/knowledge/knowledge-graph.json` is currently the canonical graph and is approximately 94 KB. It already contains explicit question references and Bloom-style cognitive levels.

The graph is valuable, but the current architecture needs automated integrity checks for:

```text
node → question
node → prerequisite
question → knowledge
question → experiment
question → misconception
experiment → knowledge
experiment → question
misconception → remediation
```

A graph reference is not evidence that the referenced content actually exists.

## 4. Content provenance policy

Every publishable content item must declare provenance using a structured object:

```js
source: {
  type: 'curriculum-standard' | 'approved-textbook' | 'teacher-authored' | 'verified-reference',
  title: '...',
  publisher: '...',
  edition: '...',
  locator: 'chapter/page/section or stable URL',
  reviewedBy: '...',
  reviewedAt: 'YYYY-MM-DD',
  status: 'draft' | 'reviewed' | 'verified' | 'published'
}
```

### Source hierarchy

1. **National curriculum standard** — scope, learning requirements, academic depth.
2. **Approved Grade 9 textbook** — sequence, terminology, canonical school-level experiments and examples.
3. **Teacher-authored material** — explanations, practice and scaffolding; must be checked against levels 1–2.
4. **External reference** — only when necessary; must be independently verified and must not silently override curriculum/textbook conventions.

Do not use an AI-generated statement as its own source.

## 5. Scientificity audit rules

Each content item must pass the following checks before publication:

### Facts

- Chemical names and formulas are correct.
- Physical/chemical properties are not overgeneralized.
- Observations are separated from interpretations.
- Conditions are stated where they affect the reaction.
- No unsupported absolute claims such as “always”, “never”, or “all”.

### Equations

- Formula syntax is correct.
- Conservation of atoms is satisfied.
- Reaction conditions are represented when educationally relevant.
- State symbols/arrows are used consistently where required by the lesson.
- The explanation matches the equation rather than merely displaying it.

### Experiments

- Apparatus and materials are realistic for a school laboratory context.
- Procedure order is scientifically and operationally sound.
- Safety-critical steps are explicit.
- Observation is not confused with conclusion.
- A control/comparison is included when the learning objective requires causal reasoning.

## 6. Grade 9 suitability rules

The target learner is a Chinese Grade 9 student. Content should therefore be:

- conceptually rigorous but not university-level;
- explicit about prerequisite concepts;
- economical in terminology;
- based on observable phenomena before abstract explanation when appropriate;
- supported by diagrams, tables or experiments when these reduce cognitive load;
- limited in mathematical complexity to what the curriculum requires;
- careful not to introduce advanced models merely because they are scientifically interesting.

### Red flags

Reject or rewrite content when it:

- requires senior-high/university chemistry to understand the main idea;
- uses unexplained advanced terminology;
- turns memorization of exceptions into the primary learning task;
- asks students to infer microscopic mechanisms that the course has not established;
- gives a technically correct but developmentally inappropriate explanation.

## 7. Question-quality rubric

Every question must be reviewed on six dimensions, each scored 0–2:

| Dimension | 0 | 1 | 2 |
|---|---|---|---|
| Scientific correctness | wrong/ambiguous | minor issue | fully correct |
| Curriculum alignment | outside scope | partially aligned | directly aligned |
| Cognitive target | accidental | roughly matched | deliberately matched |
| Answerability | insufficient data | minor ambiguity | uniquely answerable |
| Explanation quality | answer only | partial reasoning | teaches the reasoning |
| Knowledge linkage | missing/wrong | broad link | canonical IDs + prerequisites |

**Minimum publish score: 10/12.**

Any question scoring 0 in scientific correctness or answerability is automatically rejected.

## 8. Knowledge-link rules

The canonical relationship model should distinguish at least:

```text
prerequisite
supports
explains
applies-to
experiment-demonstrates
question-assesses
misconception-targets
remediation-addresses
```

Do not use a generic `related` edge when a more precise relation is known.

A learning item should be traceable both forward and backward:

```text
Lesson
  ↓
Knowledge
  ↓
Experiment / Question
  ↓
Evidence
  ↓
Misconception
  ↓
Remediation
  ↓
Recheck
  ↓
Knowledge mastery
```

## 9. Immediate remediation backlog

### P0 — block content expansion

1. Build a content-reference integrity test.
2. Detect all missing question IDs referenced by the knowledge graph and experiments.
3. Add canonical provenance metadata to all publishable content.
4. Add review status to content records.
5. Normalize experiment `knowledge`/`questions` fields to canonical `knowledgeIds`/`questionIds`.
6. Prevent assessment UI from presenting missing question records as valid assessments.

### P1 — content quality

1. Audit every existing experiment against the scientificity rubric.
2. Audit every knowledge node for Grade 9 scope.
3. Add misconception links only when a diagnostic signal is evidence-based.
4. Review cognitive-level labels instead of assuming all labels are correct because they exist in JSON.
5. Replace broad `related` relationships with typed knowledge edges.

### P2 — production content

1. Author the real question bank.
2. Build question sets by knowledge point and difficulty.
3. Add experiment-linked questions.
4. Add prerequisite-aware review sets.
5. Add transfer questions that require applying a concept in a new but Grade-9-appropriate context.

## 10. Definition of content-ready

A module is **content-ready** only when:

- provenance is present;
- scientific review is complete;
- Grade 9 scope is verified;
- every question passes the quality rubric;
- every reference resolves to an existing canonical record;
- every learning item has at least one valid knowledge relationship;
- experiment safety notes have been reviewed;
- automated content-integrity tests pass.

## 11. Next development phase

The next implementation phase is **V1.9 Content Integrity Gate**.

It should add automated tests before adding large amounts of new content. The intended order is:

```text
Content schemas
      ↓
Reference integrity tests
      ↓
Provenance / review-status contract
      ↓
Scientificity review data
      ↓
Question bank
      ↓
Knowledge-question-experiment linkage
      ↓
Learning experience polish
```

The project should not use the existence of a large knowledge graph as evidence that the course is complete. Content completeness must be demonstrated by resolved references, reviewed source provenance, valid questions, and tested learning relationships.
