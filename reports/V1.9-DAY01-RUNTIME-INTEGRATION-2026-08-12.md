# V1.9 Day 01 Runtime Integration Review — 2026-08-12

## Result

**Runtime integration is now connected, but Day 01 remains NOT READY.**

## Finding

The application content loader previously loaded questions only from `modules/questions/question-bank.json`. The newly created Day 01 diagnostic questions lived in `content/questions/day01-diagnostics.js`, so a lesson could reference their IDs while `ContentService.getQuestion()` could not resolve them.

This was a real integration defect.

## Fix

`app/content-loader.js` now imports the reviewed Day 01 diagnostic question module and merges its non-archived questions into the application-level question collection.

`app/content-service.js` now maps `misconceptionIds` into the diagnosis registry's `errors` field while preserving the existing legacy `commonMistake` / `errors` behavior.

Therefore:

```text
Day 01
  ↓
diagnosticQuestions
  ↓
ContentLoader
  ↓
ContentService.questionById
  ↓
question-knowledge-map
  ↓
misconception IDs
```

## Publication boundary

The diagnostic questions remain `status: review` and are not counted as part of the published 320-question bank. This avoids silently changing the production question-bank count while still allowing the runtime diagnosis path to resolve reviewed diagnostic objects.

## Additional correction

`modules/lessons/manifest.json` previously marked every lesson `ready: true` even though the V1.9 content audit explicitly classified the lesson set as rewrite-required. All lesson manifest readiness flags are now false and `readyDays` is empty until lessons pass the real release gate.

## Day 01 changes

Day 01 now explicitly separates:

- production practice questions
- diagnostic questions
- misconceptions

The unsafe/unverified `q-acid-004` and unresolved terminology item `q-acid-001` are removed from the Day 01 lesson flow pending correction.
